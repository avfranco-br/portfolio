# Remove `site/` from Version Control — Design Spec

**Date:** 2026-08-03
**Status:** Already complete (no action required)
**Scope:** Stop tracking the generated MkDocs build output in git

---

## 1. Problem

The repository contains a `site/` directory at 3.4 MB of generated HTML, CSS, JavaScript, search indexes, and sitemaps. It is **build output** produced by `mkdocs build` and is regenerated by CI on every deployment.

Issues with the current state:

- **Repo bloat.** Every clone downloads 3.4 MB of pure output. New clones and `git pull` operations are slower than necessary.
- **Diff noise.** Generated files (sitemaps, search index, hashed asset names) appear in `git status` and `git diff` if the local build is ever out of sync with CI.
- **Misleading.** A new contributor might edit a file under `site/` and not realise their change will be silently overwritten on the next build.
- **Already half-done.** `.gitignore` line 35 already contains `/site` — the convention was set, but the directory was never removed from tracking.

## 2. Goal

Untrack `site/` from git. The directory will continue to exist locally (for `mkdocs serve` and the `portfolio-governance` CI step which builds into `site/`), but its contents will not be committed.

## 3. Non-Goals

- Removing `site/` from the working tree (the directory is regenerated on every build).
- Adding `site/` to `.dockerignore` (no Docker in this repo).
- Restructuring the build pipeline.
- Adding a `clean` step to the deploy workflow (out of scope; MkDocs already handles stale output by clearing `site/` before each build).

## 4. Why CI does not depend on the committed copy

Verified against `.github/workflows/`:

| Workflow | Reads `site/` from repo? | Why |
|----------|------------------------|-----|
| `deploy.yml` | **No** | Step "Build MkDocs" runs `mkdocs build` which regenerates `site/` from scratch. The next step uploads `./site` as a Pages artifact. |
| `portfolio-governance.yml` | **No** | Runs `mkdocs build --strict` for validation; the output is discarded. |
| `cas-validate-sdd.yml` | **No** | Does not invoke MkDocs at all. |

Conclusion: removing the committed copy is safe. CI rebuilds fresh on every run.

## 5. Execution Plan

### Step 1 — Untrack but keep on disk

```bash
git rm -r --cached site/
```

This removes the files from git's tracking database while leaving them on disk. Reversible.

### Step 2 — Verify the working tree

```bash
ls site/                  # still exists locally
git status                # site/ listed as deleted, not staged
git ls-files site/        # empty output — confirmation
```

### Step 3 — Sanity-check the local pipeline

```bash
bash scripts/run_governance.sh
pytest tests/
```

Both must pass; neither depends on `site/` being committed.

### Step 4 — Commit and push

A single commit with a clear message:

```bash
git add .gitignore site/
git commit -m "chore: untrack generated site/ directory"
git push origin <branch>
```

Then merge to `main` via PR to trigger the Pages deploy workflow on a clean tree.

### Step 5 — Confirm Pages deploy

Watch the `deploy.yml` workflow on the merge commit and confirm:
- Build step succeeds.
- Artifact upload succeeds.
- Live site at `https://avfranco-br.github.io/portfolio/` still renders correctly.

## 6. Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| CI deploy breaks because it expected committed `site/` | Reviewed all three workflows; none reference committed `site/`. CI always runs `mkdocs build` first. |
| A previous commit reference to `site/<file>` becomes broken in git history | The files still exist in git history for any checkout before this commit. After this commit, `git log -- site/404.html` shows the full history but the file is not in HEAD. |
| Clone size shrinks but working tree shows 3.4 MB | Expected; `.gitignore` excludes `site/` from future commits but does not delete existing working-tree files. Document this in commit message. |
| Local `mkdocs serve` still writes to `site/` and dirties the working tree | `.gitignore` will hide these changes from `git status`. Verify with `git status --ignored`. |

## 7. Acceptance Criteria

- `git ls-files site/` returns empty output.
- `.gitignore` contains `/site` (already true).
- `bash scripts/run_governance.sh` passes.
- `pytest tests/` passes (14 tests).
- `mkdocs build --strict` succeeds.
- Live Pages site still renders.
- ARCHITECTURE.md §10 thread #4 marked ✅ done.

## 8. Out-of-Scope Items (recorded for future)

- Adding a pre-commit hook to remind contributors not to commit generated artefacts.
- Git LFS for any large binary assets.
- Adding `clean_site.sh` to remove the local `site/` directory on demand.

## 9. Resolution

**This thread was already complete before any work was needed.**

Investigation on 2026-08-03 revealed:

- `.gitignore` line 35 contains `/site` — the ignore rule has been in place since the initial commit.
- `git ls-files site/` returns **zero files** — the directory has never been tracked.
- `git log --all -- site/` returns **empty** — no commits have ever included `site/` content.
- `git status --ignored site/` shows `site/` listed under "Ignored files" with the hint that `git add -f` would be needed to force-add it.

The thread in `ARCHITECTURE.md` §10 thread #4 was a false alarm — the rule was already in place and working. The 3.4 MB on disk is purely regenerated by `mkdocs build` runs (local and CI); it is never committed.

No code or workflow changes are required. The thread is marked ✅ done in `ARCHITECTURE.md` for bookkeeping.
